# Web Design（アンチスロップ統合）

出典統合: frontend-design (Anthropic) + taste-skill (Leonxlnx) + ui-ux-pro-max (nextlevelbuilder)。
3つの「AIっぽさ回避」スキルを1本のワークフローに再構成。

> 住み分け: claude.ai の **artifact-design** は Artifact ページ用。こちらは**プロジェクトの実装コード**
> (React/Vue/HTML/CSS) 用。データ可視化は **dataviz** スキルに委譲。

## 0. ブリーフ読解（コードを書く前に部屋を読む）

LLMデザインが悪くなる最大要因は、ブリーフを読まず既定の見た目に飛びつくこと。まず読む:

1. **ページ種別** — SaaS LP / 消費者 LP / エージェンシー / ポートフォリオ / リデザイン / エディトリアル。
2. ** vibe語** — 「ミニマル」「Linear風」「Awwwards」「ブルータリスト」「Apple的」「B2B堅め」など。
3. **参照** — 貼られたURL・スクショ・競合ブランド。
4. **オーディエンス** — B2B調達担当 / デザイン感度の高い消費者 / 採用担当。**見た目は好みでなくオーディエンスが決める。**
5. **既存ブランド資産** — ロゴ・色・書体・写真（リデザインでは出発点）。
6. **静かな制約** — アクセシビリティ最優先・公共・規制業界・信頼第一の商取引。これらは美的好みを**上書き**する。

### Design Read を1行で宣言してから作る
> 「これは〈ページ種別〉for〈オーディエンス〉、〈vibe〉の言語、〈デザインシステム/美的家系〉寄りで作ります。」

曖昧なら**質問は1つだけ**（例: 「Linear的に綺麗め と Awwwards的に実験的、どっち寄り?」）。自信を持って推測できるなら聞かずに宣言して進む。

## 1. アンチデフォルト規律（生成AIの手癖を避ける）

既定にしない: AI紫グラデ / 暗いメッシュ上の中央ヒーロー / 等幅3枚フィーチャーカード /
全面グラスモーフィズム / そこら中の無限ループ微アニメ / Inter + slate-900。

避けるべきタイポの手癖（生成ページの最大の"tell"）:
- 見出しの1語だけ色/斜体/太字で強調。
- ラベルを全部大文字 (ALL CAPS) に。
- 内容の上に不要なラベルを足す。
- 箇条の頭に 01 / 02 / 03（本当に連番・手順・時系列のときだけ可）。
- リンク/ボタン語尾に「→」、中黒区切り「A · B · C」、スペース付きem dash「WORD — 断片」。

## 2. 3つのダイヤル（Design Read から設定）

- `DESIGN_VARIANCE`（1=完全対称 … 10=カオス）
- `MOTION_INTENSITY`（1=静止 … 10=シネマティック）
- `VISUAL_DENSITY`（1=画廊的に空ける … 10=コックピット）

目安: ミニマル/Linear系 = 5-6 / 3-4 / 2-3。プレミアム消費者 = 7-8 / 5-7 / 3-4。
実験的/エージェンシー = 9-10 / 8-10 / 3-4。信頼第一/公共 = 3-4 / 2-3 / 4-5。

## 3. 制作プロセス（2パス）

1. **設計プラン（書く前）**: 色(名前付きhex 4-6)、書体とその役割、レイアウト概念(1文＋ASCIIワイヤー)、このページ固有の原則。
2. **ブリーフ照合**: 作ったプランのどこかが「どのLPでも出す既定」になっていないか自己批判し、
   なっていれば直して「何をなぜ変えたか」を言う。固有性を確認してからコードを書く。
3. **実装**: CSS セレクタの詳細度の打ち消しに注意（`.section` と要素セレクタの margin/padding 衝突が頻出）。
4. **自己批評**: 大胆さは1箇所に集中。レスポンシブ・キーボードfocus可視・reduced motion尊重・色のアクセシビリティは最低ラインとして黙って満たす。「鏡の前でアクセサリーを1つ外す」。

## 4. スタイル/トークンDB（任意・大規模制作時）

ui-ux-pro-max は 84スタイル・192カラーパレット・74フォントペアリング・UXガイドライン等の
検索可能DBを持つ。繰り返しの制作を仕組み化するなら `docs/bridges.md` の手順で導入し、
プロジェクトごとにデザインシステムを生成して本スキルの入力にする。

## 事業への適用
- **A 自社SaaS/アプリ**: 製品内UIは VARIANCE 控えめ・DENSITY 高め。信頼と操作性優先。
- **C 資料・集客**: LP/ポートフォリオは固有性を出す。クライアント競合を参照に差別化。
